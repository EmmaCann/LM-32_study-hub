## Un sistema, due responsabilità

Una macchina virtuale presenta al sistema operativo guest un ambiente hardware virtuale. Su Linux, **KVM** abilita l’esecuzione virtualizzata sulla CPU, mentre **QEMU** gestisce il processo della VM e può emulare i dispositivi.

| Componente | Responsabilità                                      |
| ---------- | --------------------------------------------------- |
| KVM        | Virtualizzazione della CPU e interfaccia del kernel |
| QEMU       | Modello della macchina e dispositivi in userspace   |
| Guest      | Sistema operativo che gira nella macchina virtuale  |

## Dal processo alla vCPU

QEMU usa l’interfaccia di KVM per creare una VM e le sue vCPU. Un thread della vCPU entra nel kernel con la chiamata **KVM_RUN**. Il guest esegue poi sulla CPU fisica usando le estensioni di virtualizzazione.

> Una vCPU non è necessariamente un core fisico dedicato: il sistema host pianifica i thread che ne eseguono il lavoro.

## Quando il controllo torna all’host

Alcuni eventi richiedono l’intervento dell’host. Una VM exit trasferisce il controllo dal guest all’hypervisor: KVM può gestire l’evento direttamente oppure restituire a QEMU un motivo di uscita dall’interfaccia KVM_RUN.
